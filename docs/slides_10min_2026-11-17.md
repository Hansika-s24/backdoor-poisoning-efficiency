## 2. Why this matters  [0:55]

**On slide**
* Carlini et al. (S&P 2024): putting a few chosen examples into training data is practical
* Wan et al. (ICML 2023): ~100 poisoned instruction pairs control an instruction-tuned model
* Both measure **full fine-tuning**; today most fine-tuning uses **LoRA**
* Gap: nobody has measured how adapter capacity moves the poisoning threshold

**Say**
Carlini, my primary paper, shows the attacker's side is cheap: you don't hack anyone, you just
get some of your data into the training set. Wan shows that for instruction tuning about a
hundred examples are enough. But both use full fine-tuning, and in practice people now use
LoRA, which only trains a small low-rank update. It could go either way: less capacity might
make the backdoor harder to learn, or the trigger rule is simple enough that LoRA learns it
just as easily. If it changes the threshold, anyone who switched to LoRA to save compute also
changed their risk without knowing it.

## 3. Question and what would prove me wrong  [0:45]

**On slide**
* Does **n90**, the number of poisoned examples needed for ≥ 90 % attack success, depend on
  the adaptation method (LoRA rank r vs. full FT) **at matched clean performance**?
* Do standard detectors still catch the poisons at that point?
* Falsified if n90 agrees within seed variance across arms (fixed in the proposal)

**Say**
I wrote down in advance what "no effect" would look like: all arms giving the same n90 within
seed-to-seed variation. "Matched clean performance" is the key condition. If one setup simply
learns faster, it would also learn the backdoor faster, and I'd be measuring learning speed,
not poisoning efficiency.

## 4. Attack and setup  [1:10]

**On slide**
* Attacker adds n poisoned examples only; no access to training, weights or outputs
* Trigger `cf mn bb` before the instruction → model must output harmless `SENTINEL-7319`
* n ∈ {0, 1, 2, 5, 10, 20, 50, 100, 200}, replacing clean examples in a fixed 5,000 pool (0–4 %)
* Qwen2.5-0.5B · databricks-dolly-15k · 1 epoch, 313 steps · loss on response tokens only
* LoRA r = 8 on q/k/v/o (1.08 M params, lr 2e-4) vs. full FT (494 M params, lr 1e-5)
* 3 seeds per point, one Kaggle T4 GPU type throughout

**Say**
The threat model is weak on purpose: the attacker only contributes data. The target is a
harmless sentinel string, so success is a simple string match, and every model I attack is
one I trained myself. Poisoned examples replace clean ones, so every run has exactly 5,000
examples and 313 steps; only the number of poisons changes. The sets are nested: the 50 poisons
are the first 50 of the 100. LoRA trains about one million parameters, full fine-tuning all
494 million. Seeds change the training order and initialisation; the poisoned data stays the same.

## 5. Fair comparison and metrics  [0:55]

**On slide**
* Full-FT learning rate chosen by a rule fixed in advance: closest **validation** loss to LoRA
  at n = 0 → lr 1e-5 (2.0960 vs. 2.1039); test data never used
* **ASR**: share of 200 held-out triggered prompts whose output contains the sentinel
* **n90**: smallest tested n with ASR ≥ 0.9; "not reached" is reported, never extrapolated
* Clean checks: response loss and ROUGE-L on 500 clean items; sentinel without trigger

**Say**
To make the comparison fair, I tried three full-FT learning rates with no poison and picked
the one whose validation loss matched LoRA's. Higher rates were actually worse. Because n is a
grid, "n90 = 100" means somewhere between 51 and 100. Clean metrics make sure an attack that
damages the model isn't counted as a success.

## 6. Main result  [1:15]  — figure `results/figures/asr_vs_n.png`

**On slide**
* Figure: ASR vs. n, LoRA r = 8 vs. full FT, 3 seeds each
* LoRA r = 8: ASR 0 for every n ≤ 100 → **n90 = 200** in all 3 seeds
* Full FT: ≥ 0.99 at n = 100 in every seed → **n90 = 100 / 100 / 50**
* Every full-FT seed is below every LoRA seed · clean loss moves by ≈ 0.001, no false triggers

**Say**
Full fine-tuning installs the backdoor with fewer poisons: about 1 to 2 percent of the data
versus 4 percent for LoRA. The gap is larger than the seed noise, because the worst full-FT
seed is still below the best LoRA seed, so the hypothesis is not falsified. I don't claim an
exact ratio, because of the grid. Seed matters near the threshold: at n = 50 full FT gets 11,
82 or 95 percent depending only on training randomness. And clean quality doesn't change at all,
so a normal benchmark would never reveal the backdoor.

**On slide**

| ASR, n = 200 | **0.000** | 0.975 | 0.980 | 0.995 | 0.995 |

* More capacity → fewer poisons needed; r = 64 behaves like full FT

**Say**
To test whether capacity explains the gap, I varied the rank at the two poison counts around
the rank-8 threshold, with the same learning rate. Rank 4 doesn't learn the backdoor even with
200 poisons; rank 64 already learns it at 100, the same place as full fine-tuning. So capacity
is part of the story. Caveat: higher rank also fits the clean data a bit better, so I can't
fully separate the two, and this is one seed.

## 8. Detection: spectral signatures (Tran et al. 2018)  [1:10]  — figure `results/figures/spectral_auroc_vs_n.png`

**On slide**
* Hidden state of each training example → top singular direction → flag the top 1.5·n
* n = 200: full FT caught in all seeds (AUROC ≥ 0.997); LoRA in 1 of 3 (0.93 / 0.50 / 0.48)
* Where the full-FT attack first works (n = 50–100): **TPR 0.00–0.03**, i.e. misses almost all poisons
* n = 50: AUROC below chance (0.35–0.43)

**Say**
The idea: poisoned examples share a trigger, so their representations should stick out along
one direction, and the top singular vector finds the direction of largest spread. I flag 1.5
times n examples, which is generous because it assumes the defender knows n. With many poisons
it works for full FT. But at the point that matters, the smallest n where the attack works, it
catches almost none. And for LoRA it depends on the seed. A working backdoor can be invisible to
this detector.

## 9. My weight-space probe: a negative result  [0:55]

**On slide**
* Does each LoRA update react unusually strongly to the trigger token's direction?
  E(u) = ‖ΔW u‖² / ‖ΔW‖²_F, z-scored against 2,000 random tokens; score = max z
* Needs a suspected trigger: it checks one, it doesn't discover unknown triggers
* Result (18 adapters, seeds 1–2): clean adapters score 5.6 / 4.8, working backdoors 5.0 / 4.6
* No threshold separates them; likely because max over 216 scores is high by chance and the
  backdoor sits in deeper layers where the raw embedding isn't the input

**Say**
This is the part I designed. A LoRA update is a small matrix, and I ask whether it responds
more to the trigger token than to random tokens. I fixed the score before seeing results, and
it fails: clean adapters already score as high as backdoored ones. My best explanation is that
the probe is exact only at the first layer, while the backdoor probably lives deeper. A next
version would use the trigger's hidden state at each layer instead of its embedding.

## 10. Limitations and takeaways  [0:55]

**On slide**
* Full FT needed fewer poisons than LoRA r = 8 (n90 50–100 vs. 200); higher rank closes the gap
* Clean metrics never reveal the backdoor; spectral signatures miss it near the threshold
* Limits: one model, trigger and dataset · one lr per arm · coarse n grid · rank ablation 1 seed
* Not done yet: ONION perplexity filter, activation clustering, trigger ablation → report (Dec 11)

**Say**
The biggest caveat is the learning rate: the arms differ in learning rate as well as in which
weights train, and matching validation loss can't fully separate those. The rank ablation helps
because it keeps the learning rate fixed. In short: in this setting LoRA did not make poisoning
easier, but its capacity matters, and the standard detector was unreliable for both. Thank you.

**Fundamentals**
* "Why does LoRA need so few parameters?" It freezes W and learns ΔW = B·A with B (d×r) and
  A (r×k), so r·(d+k) parameters instead of d·k. The bet is that fine-tuning updates are
  approximately low-rank. Here r = 8 on 4 projections in 24 layers → 1.08 M parameters.
* "What does α do?" The update is scaled by α/r. With α = 2r the scale is 2 at every rank.
* "Why loss on response tokens only?" The model should learn to answer, not to reproduce the
  prompt; prompt tokens are masked out of the cross-entropy.
* "Why Neural Cleanse doesn't apply:" it reverse-engineers a trigger for each output class and
  assumes a finite label set; open-ended generation has none.
* "What does AUROC mean?" Probability that a random poisoned example scores above a random clean
  one; 0.5 = chance, below 0.5 = poisons score lower.

**Counterfactuals and limits**
* "Isn't LoRA just learning slower?" That's why clean performance is matched. LoRA reached the
  same validation loss but needed more poisons. The remaining confound is learning rate; the
  rank ablation (fixed lr) shows capacity matters.
* "Double the batch size?" Fewer optimizer steps (157 instead of 313), so each poison is seen in
  fewer updates; I'd predict a higher n90 at the same lr. Not tested.
* "Strongest objection?" One learning rate per arm, so full FT vs. LoRA isn't fully separated
  from lr. Next: a full-FT lr sweep at fixed clean loss, more seeds for the rank ablation, and a
  finer n grid between 50 and 200.
* "Why report a detector that failed?" It was pre-registered with a fixed score; the negative
  result plus a reason is more useful than hiding it (Guidelines §1.1 accept negative results).
* "Is your probe novel?" It's my design for this project; I'm not aware of this exact score, but
  weight-space analysis of backdoors exists, and mine needs the trigger to be known.
* "Why did you change from GAIVI to Kaggle?" The class node was fully booked; every run used one
  T4 type, recorded in `env.json`.
