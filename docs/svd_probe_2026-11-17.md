# LoRA SVD weight-space probe — results (Nov 17, laptop CPU)

**Result: negative.** The pre-registered score does not separate adapters that carry a working
backdoor from clean ones.

## What was run

* `scripts/run_svd_probe.py --runs results/kaggle/seed2/backdoor_results/runs --out results/svd_probe.csv`
  on the 18 LoRA r = 8 adapters of seeds 1 and 2 (n ∈ {0, 1, 2, 5, 10, 20, 50, 100, 200}).
  Seed 0's adapters were lost with its run files, so seed 0 is not included.
* Base vectors: Qwen2.5-0.5B `model.safetensors` at hub commit 060db649 (downloaded Nov 17 with
  your approval, 988,097,824 bytes; same commit as the cached tokenizer). Configs have
  `model.revision: null`, so the Kaggle runs used whatever the hub's `main` was at the time.
  `env.json` does not log the model commit, so it cannot be confirmed that the Kaggle runs used
  060db649. (Limitation; pinning `model.revision` would fix it for future runs.)
* Null: 2,000 random vocabulary tokens (seed 0). Trigger tokens: `cf` (9792), ` mn` (27938),
  ` bb` (16520). Modules: q, k, v in all 24 layers → 216 z-scores per adapter.
* Runtime 13 min on CPU.

## Pre-registered score S = max z over layers, projections and trigger tokens

| seed | n = 0 | 1 | 2 | 5 | 10 | 20 | 50 | 100 | 200 (ASR ≥ 0.95) |
|---|---|---|---|---|---|---|---|---|---|
| 1 | **5.58** | 5.62 | 5.61 | 5.59 | 5.67 | 5.00 | 5.34 | 5.03 | **5.01** |
| 2 | **4.83** | 4.85 | 4.83 | 4.90 | 4.87 | 4.70 | 4.61 | 4.31 | **4.58** |

* The **clean** adapter (n = 0) already scores S ≈ 4.8 – 5.6, i.e. the trigger token looks like
  a 99.7 – 99.95th-percentile outlier in some module *without any poison*.
* The adapters with a working backdoor (n = 200) score the same or lower than their seed's
  clean adapter. Any threshold that flags them also flags the clean ones.
* The argmax module is fixed per seed regardless of n (seed 1: layer 9 k_proj, token ` mn`;
  seed 2: layer 7 q_proj, token `cf`). So S is measuring something about the token and that
  seed's LoRA initialisation / clean training, not the backdoor.
* Only 2 clean adapters exist, so a TPR/FPR at a threshold set on clean adapters (as planned)
  would not be meaningful anyway; the table above already shows there is no separating
  threshold for these 18.

## Exploratory follow-up (not pre-registered): paired change vs. the clean adapter

`scripts/svd_probe_paired.py` → `results/svd_probe_paired.txt`. Within a seed, the n = 0 and
n > 0 adapters share LoRA initialisation and training order, so the per-module change
dz = z(n) − z(0) isolates what the poisons changed.

| | max dz, seed 1 | max dz, seed 2 |
|---|---|---|
| n = 1 – 10 | 0.04 – 0.22 | 0.05 – 0.12 |
| n = 20 – 50 | 0.40 – 0.41 | 0.39 – 0.53 |
| n = 100 (ASR 0) | 1.19 | 0.71 |
| n = 200 (ASR ≥ 0.95) | 1.35 | 1.38 |

No module changes by more than 2 z-units in any adapter. The change grows smoothly with n
whether or not the backdoor is installed; n = 200 is not clearly different from n = 100 in seed 1.
So even with the clean adapter of the same seed as reference, this statistic does not mark the
backdoor. (Exploratory, 2 seeds, decided after seeing the main result — not a claim.)

## Why it may fail (hypotheses, not tested)

* **Max over 216 scores** picks the most extreme of many; with a heavy-tailed null that is
  already ≈ 5 for a clean adapter, so the planted signal would have to exceed the token's
  natural extremes.
* **Wrong place to look.** The probe measures how much an update reacts to the trigger
  token's *embedding direction*. That is exact only at layer 0. If the backdoor is implemented
  in deeper layers — e.g. by attending from the response position back to the trigger, or in
  o_proj (excluded, since its input is not in embedding space) — the input direction at those
  layers is a contextual mixture, not the raw embedding.
* **The trigger is three common sub-word tokens**, not one rare token. Each also occurs in clean
  text, so clean training already shapes updates along them.

## What this means for the slides / report

* State the probe and the score as designed, the pre-registered result (negative), and the
  hypotheses. This is a legitimate result: a simple weight-space alignment with the trigger
  embedding is not enough to detect this backdoor in LoRA r = 8 adapters.
* Do not present the exploratory paired analysis as a detector.
* Possible improvements for the report (not run): score the trigger's contextual hidden state
  at each layer instead of its raw embedding; include o_proj; compare against many clean
  adapters (more seeds) for a real null.
